# Simplified Endpoints Mapping

## 1. Token Registration Endpoint
- **URL:** `POST /api/settings/push-token`
- **Purpose:** Registers a new FCM token generated by the React Native app.
- **Expected Payload:**
  ```json
  {
    "token": "fcm_token_string_here",
    "deviceType": "android"
  }
  ```
- **Backend Action:** Upsert the token into the database (e.g., `SiteSettings.fcmTokens` or `User.fcmTokens`). Return `200 OK`.

## 2. Mercado Pago Webhook (Existing Integration)
- **URL:** `POST /api/mercadopago/webhook`
- **Purpose:** Receives payment status updates from Mercado Pago.
- **Expected Payload:** Standard Mercado Pago webhook payload (`{ action, data: { id } }`).
- **Backend Action (New Addition):** After verifying and processing the payment, dispatch a push notification to the site owner's FCM tokens.

### FCM Push Payload Example (Internal Backend Usage)
When dispatching the push notification via Firebase Admin inside the webhook, the backend MUST use the following structure so the Mobile App can parse it correctly:

```javascript
// Example using firebase-admin
const message = {
  notification: {
    title: 'Nova Venda!',
    body: 'Uma venda de R$ 99,00 foi aprovada.',
  },
  tokens: user.fcmTokens, // Array of strings
};

const response = await admin.messaging().sendMulticast(message);

// Cleanup logic example:
if (response.failureCount > 0) {
  const failedTokens = [];
  response.responses.forEach((resp, idx) => {
    if (!resp.success && resp.error?.code === 'messaging/registration-token-not-registered') {
      failedTokens.push(user.fcmTokens[idx]);
    }
  });
  // TODO: Remove failedTokens from the database
}
```
